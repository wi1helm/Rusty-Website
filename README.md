## Project Structure

Here is a quick explanation of the important folders and files.

### Folders

#### `src/`

The main Rust backend.

This is where the application logic lives, such as:

- API routes
- Database logic
- Validation
- Sessions/authentication
- Business logic
- Tests

Think of `src/` as the actual backend application.

---

#### `frontend/`

The frontend of the application.

This contains the pages and UI that users interact with.

The frontend is mounted into the Docker server container so changes can be accessed by the server.

---

#### `migrations/`

Contains database migrations.

Migrations are SQL files that describe changes to the database.

For example:

```sql
ALTER TABLE users ADD COLUMN email TEXT;
```

Instead of manually changing the database, we create a migration and let SQLx apply it.

Migrations are normally applied in order.

For example:

```
Migration 1 -> Create users table
Migration 2 -> Add email to users
Migration 3 -> Create sessions table
```

If a migration has already been used/shared, don't normally edit it.
Create a new migration for the next database change.

---

#### `.sqlx/`

Contains information generated by SQLx for offline query checking.

SQLx can check SQL queries against the database during compilation.

For example:

```rust
sqlx::query!("SELECT id, username FROM users");
```

SQLx can check that:

- The SQL is valid
- The table exists
- The columns exist
- The returned types match what Rust expects

The `.sqlx/` directory allows this checking to work without needing a live database during compilation.

If database queries or database structure change, the SQLx metadata may need to be updated.

---

#### `docs/database/`

Documentation about the database.

Currently this contains the database ER diagram.

The ER diagram shows:

- Database tables
- Columns
- Relationships between tables

This is useful when you want to understand the database without reading all the migrations.

---

#### `scripts/`

Contains helper scripts for development.

These can be used for things such as:

- Updating SQLx metadata
- Running database commands
- Preparing the database
- Cleaning old/generated files
- Other development tasks

The goal is to avoid having to manually run complicated commands.

---

#### `.idea/`

IDE configuration files.

These are created by JetBrains IDEs such as IntelliJ IDEA or RustRover.

They are not part of the actual application.

---

### Important Files

#### `Cargo.toml`

The main configuration file for the Rust project.

It contains information about the project and its dependencies.

For example:

```toml
[dependencies]
axum = "..."
sqlx = "..."
redis = "..."
```

When the Rust application needs a new library, it is normally added here.

---

#### `Cargo.lock`

Contains the exact versions of Rust dependencies used by the project.

`Cargo.toml` can allow a range of versions, while `Cargo.lock` records the specific versions that Cargo resolved.

This helps make sure developers and build servers use the same dependency versions.

For an application, `Cargo.lock` should normally be committed to Git.

---

#### `Dockerfile`

Contains the instructions for building the Rust application's Docker image.

Docker uses this file to build the server container.

The Dockerfile also runs the project's tests before starting the application.

---

#### `compose.yaml`

The Docker Compose configuration.

It describes all the containers needed to run the project.

Currently there are four services:

- server
- postgres
- redis
- sqlx-tools

You can start the normal environment with:

```bash
docker compose up
```

---

#### `.dockerignore`

Similar to `.gitignore`, but for Docker.

It tells Docker which files should not be included when building the Docker image.

This helps keep builds smaller and faster.

---

#### `.gitignore`

Tells Git which files should not be tracked.

This is normally used for things like:

```
target/
.env
temporary files
IDE files
```

## Docker Services

### `server`

The Rust application.

It is built using the Dockerfile and runs on port 3000.

```yaml
ports:
  - "3000:3000"
```

The server also receives the database and Redis connection URLs through environment variables:

```
DATABASE_URL=postgres://admin:password@postgres:5432/database
CACHE_URL=redis://redis:6379
```

---

### `postgres`

The PostgreSQL database.

The database is running inside its own Docker container.

The default configuration is:

- Username: `admin`
- Password: `password`
- Database: `database`

PostgreSQL data is stored in a Docker volume so that the database can survive container recreation.

---

### `redis`

Redis is used as a fast in-memory data store/cache.

It can be used for things such as:

- Caching
- Sessions
- Temporary data
- Rate limiting
- Other short-lived data

A simple way to think about it:

```
PostgreSQL -> Permanent application data
Redis      -> Fast temporary/cache data
```

---

### `sqlx-tools`

A development-only container for SQLx/database tools.

It is part of the `tools` Docker Compose profile, so it does not start with the normal:

```bash
docker compose up
```

It can be used when database or SQLx-related commands need to be run inside a consistent Rust environment.

---

## Docker Volumes

### `postgres_data`

Stores PostgreSQL's database files.

This means the database data can survive when the PostgreSQL container is recreated.

### `cargo_registry`

Used by the `sqlx-tools` container to cache Rust packages.

This prevents Rust dependencies from having to be downloaded again every time the tools container is recreated.
